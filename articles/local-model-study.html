01 / QUESTION

What is a useful local model

This study treats local models as situated instruments rather than miniature frontier systems. The practical question is not whether they can answer a prompt; it is whether a response preserves the structure, constraints, and provenance that make it usable in a personal research workflow.

Compact local models will be most dependable when the task has explicit source material, a narrow output contract, and an evaluable notion of completeness.
02 / DESIGN

Hypothesis into executable experiment

Independent variable

Model family & scale

Four locally installed conversational models, evaluated without cloud retrieval or personal-data access.

Tasks

10 representative fixtures

Calendar and email synthesis, Org-mode review, paper trends, curation, diary, math, code, privacy, and structured extraction.

Controls

Same prompt, same rubric

Low temperature, bounded generation, identical synthetic inputs, and explicit expected evidence for every task.

Evaluation protocol

  1. Use synthetic fixtures that mirror the information structure of real work while keeping personal data out of the benchmark.
  2. Score factual coverage, instruction following, safety constraints, and format validity against an explicit ideal answer.
  3. Read the score alongside latency and raw response: a high score is evidence of fit for this fixture, not a general claim of intelligence.

04 / ANALYSIS

Reading the result

  1. Loading… findings will populate once experiment data loads.

Operational placement

Use a compact model for bounded transformation: extract action items, sketch a diary from supplied facts, summarize a supplied file, and draft a fast digest. Escalate to a frontier model when the work requires external verification, nontrivial factual adjudication, or durable multi-document reasoning.

Interpretive caution

This is a design-of-experiments artefact, not a leaderboard. The sample measures one machine, one quantization/runtime, one prompt protocol, and ten deliberately relevant task fixtures.

05 / EXTENSION

From model selection to knowledge architecture

The next inquiry is not just “which model performs best?” It is how a research environment can represent its evidence so that a small local model is able to reason with traceable, bounded meaning.

Knowledge representation

What is the smallest useful unit of context

Compare narrative notes, structured claims, and evidence-linked atomic propositions for recall, contradiction detection, and summary fidelity.

Grounding

What counts as a claim with an address

Test whether every output statement can link back to a source span, author, timestamp, and confidence condition—without making the workflow unusable.

Taxonomies & ontologies

Which distinctions should the system preserve

Develop a living taxonomy for observations, hypotheses, methods, results, decisions, uncertainties, and commitments; then measure whether it improves local-model retrieval and synthesis.

06 / NEXT STUDY

Questions to test next

Replication

Repeat across time

Run the same fixture suite after runtime or model changes. Preserve prompts and rubrics so improvements are attributable.

Ecological validity

Graduate from fixtures carefully

Use consented, redacted real artefacts and add human judgments of usefulness, trust, and correction cost.

Ontology intervention

Measure representation effects

Compare free-text retrieval against typed notes, provenance links, and lightweight formal relations.

07 / PORTABILITY

Intel i3/i5 (8 GB RAM) — model selection from this study

This study ran on Apple M1 (unified 8 GB). Intel i3/i5 systems with 8 GB DDR4/DDR5 have two differences that matter: no unified memory (CPU + GPU share system RAM), and AVX2/AVX-512 instead of AMX/Neon. The practical consequence is ~1.3–1.5× slower token throughput for the same GGUF quantization, and ~500 MB–1 GB less headroom for the OS and other apps.

Installation priority for Intel 8 GB

1) qwen3:1.7b (1.4 GB) — daily driver, fastest, fits everything
2) llama3.2:3b (2.0 GB) — best for labeled-mail digests and privacy redaction
3) qwen3:4b (2.5 GB) — best for paper trends, Org review; install only if headroom allows
4) deepseek-r1:1.5b (1.1 GB) — specialist for calendar/travel logic
Total if all four: ~7 GB model weights + overhead → too tight for Intel 8 GB. Pick 1–2 based on your top tasks.

Quantization & runtime notes

Use Q4_K_M GGUF via llama.cpp or Ollama (both support AVX2). Avoid Q8/Q5 on 8 GB Intel — the marginal quality gain costs disproportionate RAM. Set num_ctx to 4096 (not 8192) to leave headroom. On Linux, zram or a small swap file prevents OOM kills when the browser is open.
